# DECISIONS.md — Lyric Reader

Every judgement call made while Nahom slept. Each entry: what I chose, why,
and how to change it. Nothing here is load-bearing — veto anything.

## Reader look & feel

1. **Muted trail = white at 28% opacity, NOT `--muted-foreground`.**
   The design system's dark `--muted-foreground` (0.72 lightness) renders as
   medium grey — far too loud next to the mockup's ~25–30% white trail.
   Trail blocks use `#fff` at `var(--trail-opacity: 0.28)` with a fade mask.
   → Change: edit `--trail-opacity` in `app/src/index.css`.

2. **Primary indigo (266) never touches reader body text.**
   It's reserved for library UI: buttons, progress bars, the "LYRIC READER"
   eyebrow, focus rings. The reader stays pure black + white only.
   → Change: it's just usage discipline; no token to flip.

3. **Current-sentence auto-shrink tiers.**
   Mockup shows one huge sentence; long sentences must not overflow.
   ≤90 chars → 2.6rem, ≤170 → 2.1rem, ≤280 → 1.7rem, longer → 1.4rem,
   all × the user's font-scale (0.8–1.4, A−/A+ in the overlay).
   → Change: `currentFontSize()` in `app/src/components/Reader.tsx`.

4. **Sentence transition: 300ms ease-out, rise + settle.**
   `translateY(10px) scale(0.985)` → rest, opacity 0.35 → 1.
   Transform/opacity only — no layout work per advance, so no jank.
   Disabled under `prefers-reduced-motion`.
   → Change: `@keyframes sentence-in` in `app/src/index.css`.

5. **One sentence per gesture, guaranteed by construction.**
   Navigation uses functional `setPos(p => step(pages, p, dir))` so rapid
   gestures can't skip. Wheel input is locked for 600ms after each step;
   taps are split into thirds (top = back, bottom = forward, middle = overlay);
   pointer swipes need 48px vertical travel. Keys: arrows/space/page keys.
   → Change: constants at the top of `Reader.tsx`.

6. **Headings render in the serif face when current.**
   Gives chapter titles a "title card" moment; in muted blocks they stay
   small like everything else. (Serif file is Noto Serif Georgian 600,
   self-hosted — see 12.)

7. **Bullet hairlines: nested levels only.**
   Level-0 bullets get indent + no hairline (their "parent" is prose, and a
   line to nowhere looked wrong). Nested bullets (level ≥ 1) get a 1px hairline
   at the parent's indent, white at 22% — the thread-line effect.
   Muted blocks use a `•` marker + indent instead of hairlines.
   → Change: `Reader.tsx` (`bullet-hairline`) and `TrailLine`.

8. **Desktop: content column capped at 56rem, centered.**
   The mockup is a phone; at laptop widths uncapped text ran 900px+ wide.
   Phone keeps the mockup's ~12% side margins (`max(1.5rem, 12%)`).

9. **Overlay: hidden until you tap the middle third, auto-hides after 3.5s.**
   Contains ← Library, title, `Page x of y · z%`, thin primary progress bar,
   and A−/A+ font controls. Nothing else lives on the reader screen.

10. **End of book: clamps.** No "finished" screen in v1 — advancing past the
    last sentence just stays put. (Easy to add later if wanted.)

## Pagination & position

11. **EPUB / TXT / paste: ~14 sentences per page. PDF: one reader page per PDF page.**
    The 14-sentence chunk keeps the muted trail from becoming a wall while
    keeping page turns infrequent. PDF pages are natural boundaries already.
    → Change: `SENTENCES_PER_PAGE` in `app/src/lib/extract.ts`.

12. **Reading position = (page, sentence) in IndexedDB, saved debounced
    (500ms) + flushed on `pagehide`. The last-open book id is remembered in
    localStorage, so reopening the app drops you straight back into reading.**
    → Change: `app/src/lib/db.ts`, `App.tsx`.

## Extraction

13. **EPUB parsed with jszip + a hand-rolled OPF/spine walker, not epubjs.**
    Smaller bundle, fully deterministic, no extra dependency. Handles
    h1–h6, p/div/blockquote, nested ul/ol with depth.
14. **PDF text rebuilt by grouping glyphs into lines (y-tolerance 2.5px).**
    Good for single-column prose; two-column layouts may read across columns —
    documented as a known limit.
15. **Sentence splitter = `Intl.Segmenter` + abbreviation merge rules**
    (Dr., e.g., Fig., decimals, initials, ellipses). Rules live in
    `app/src/lib/segment.ts` and are unit-tested.
16. **DOCX not included in v1.** Spec listed it as "if time"; PDF/EPUB/TXT +
    paste-text cover the MVP. Say the word and I'll add mammoth.js.

## Fonts, icons, PWA plumbing

17. **Fonts self-hosted in `/fonts`, precached by the service worker:**
    Geist Regular + SemiBold and Geist Mono Regular from the `geist` npm
    package; Noto Serif Georgian 600 (latin + latin-ext subsets) fetched from
    Google Fonts at build time. If a file ever goes missing the stacks fall
    back to system fonts — the app still works.
18. **Icons generated by a zero-dependency Node script**
    (`app/scripts/make-icons.mjs`): "lyrics bars" motif — five primary-indigo
    bars on pure black, 192/512 + maskable-512 with safe-zone padding.
19. **Service worker via `vite-plugin-pwa` (generateSW).**
    Precaches everything including the pdf.js worker (cache cap raised to
    12MB); `navigateFallback: index.html` so reloads work offline.
    Chose the plugin over a hand-rolled SW for reliability.
20. **App is dark-only** (`<html class="dark">` forced) — the whole product is
    the black reader; a light theme would fight the mockup.

## Content

21. **Sample book "Sample — The Midnight Staircase"** (60 sentences, 5 pages)
    is original prose written for testing: paragraphs, headings, nested
    bullets. Seeded once on first run (guarded against double-seeding).

## Post-launch: self-generating assets (Oct 18, ~23:57 EAT)

- **Context:** The GitHub connector push is UTF-8-text-only and this environment's browser file-upload is blocked, so the font (.woff2) and icon (.png) binaries could not be committed to the repo — which Vercel needs in order to build from GitHub.
- **Decision:** The build now generates its own binaries. `app/scripts/copy-fonts.mjs` copies the five fonts from the `geist` and `@fontsource/noto-serif-georgian` npm packages into `public/fonts`, and the existing `scripts/make-icons.mjs` draws the three PNG icons — both wired as `prebuild` in `app/package.json`, so local builds and Vercel builds produce identical output with zero binaries in git. The generated files are git-ignored.
- **Verified:** deleted all local font/icon binaries, `npm run build` regenerated everything, dist complete, reader e2e suite still 7/7.
- **Veto/change:** to pin exact font files instead, commit the binaries with a local git client and remove the `prebuild` script.

## v2: reference UI adoption + the 4 fixes (Oct 19, 2026)

22. **Kept our three-zone stage instead of the reference's translating track.**
    The reference renders every sentence in one track that translates to keep the
    current one in place; our layout (muted top block / big centre sentence /
    muted bottom block, 10/10-approved against the mockup) produces the same
    visual with far simpler snap semantics, and it keeps "exactly one sentence
    per gesture" true by construction. Restyled to the reference tokens
    (sizes, colours, heading/bullet styles, hairline progress bar, stage mask).
    → Change: rebuild the stage as a single translating track in `Reader.tsx`.

23. **Trail/upcoming are settings-driven now; --trail-opacity is gone.**
    Trail uses `--lr-ct` (default white) × `--lr-to` (default 30%), upcoming is
    the same colour at 55% of that opacity — the reference's past/dim two-step
    fade, preserving the v1 30%-white look Nahom approved. Opacity slider
    10–100, colour picker with Default reset.
    → Change: the two sliders + Default buttons in Settings.

24. **Main sentence: 30px base (reference --fs) × the old shrink tiers.**
    Tiers are now multipliers (1 / 0.78 / 0.62 / 0.5) of the Main size setting
    (18–48), so long sentences still fit without scrolling and A−/A+ (now
    ±2px on the same setting) and the slider stay in sync. Old legacy
    `font-scale` localStorage is migrated once into `mainSize`.
    → Change: `currentFontPx()` in `Reader.tsx`.

25. **Headings follow the reference exactly: primary, uppercase, letterspaced.**
    The v1 serif "title card" for the current heading is gone — the chosen
    Settings font now governs every typeface, so headings stay on-brand
    instead of fighting a font choice. Current heading = 0.6× main size.
    → Change: `.cur-heading` / `.trail-h` in `index.css`.

26. **Bullets always get the hairline (reference style), nested or not.**
    v1 only drew hairlines for nested levels; the reference draws the 1px
    trail-colour border + 12px padding on every bullet. Indent grows 18px per
    nesting level in both current and muted blocks.
    → Change: `.trail-li` / `.bullet-wrap` in `index.css`.

27. **Top bar is always visible (reference #bar), not tap-to-reveal.**
    `← Library | page button "3 / 7" | A− A+ gear`, 14px muted row, accent bg
    on :active, hairline indigo progress under it. The old middle-tap overlay
    is removed; its middle-third tap now opens the action popup.
    → Change: `Reader.tsx` header.

28. **Popup = ONE centred card, staggered rows (fix 2).**
    Card ~200ms ease-in; rows fade+rise with 50/100/150ms delays,
    transform/opacity only (disabled under prefers-reduced-motion).
    Actions work: Highlight = sentence-level wash
    `color-mix(in oklch, --lr-hl 42%, transparent)`; Bookmark = primary dot
    after the text + entry in the jump sheet; Copy = clipboard + transient
    "Copied" row state. Marks persist per book in IndexedDB ("marks" store,
    DB v2 — additive, old installs migrate cleanly; marks die with the book).
    → Change: popup block in `Reader.tsx`, `lib/db.ts`.

29. **Jump sheet: typed input is the hero (fix 1), slider is gone.**
    Numeric input (inputMode) + "of N pages" + Go button, Enter submits.
    Non-numeric → inline hint, stays open. Numeric out-of-range → clamps to
    1..N, shows the hint, and the reader still jumps to the clamped page
    (sheet stays open so the hint is seen). Below: tappable section list
    (pages whose first sentence is a heading) and, if any, bookmarked pages.
    → Change: `submitJump` in `Reader.tsx`.

30. **Bottom nav: hidden by default, hot-zone reveal (fix 3).**
    « prev section ‹ prev page › next page » next section; section = nearest
    heading-first page (book start/end when none). Reveal: pointer hover in
    the bottom 15% (desktop), tap in the bottom hot-zone (touch), ~1.2s on
    page change, keyboard focus. Auto-hide 2.5s. Hot-zone tap NEVER advances
    — it only shows (or hides) the bar. transition 250ms.
    → Change: `showBar`/`hideBar` and the pointer handler in `Reader.tsx`.

31. **Settings is a page, reachable from two gears (fix 4).**
    Gear in the reader top bar and the library header both open it; Back
    returns to where you came from. No settings UI remains on reader/library
    screens. Settings persist in localStorage and apply live through the
    --lr-* CSS variables (also covering the library + preview card).
    → Change: `components/Settings.tsx`, `lib/settings.tsx`, `App.tsx`.

32. **Library restyle per reference:** 28px tight-tracking headline, "Start
    reading a book" primary CTA (label wrapping the file input), inline paste
    area + "Read pasted text" button, card rows with × delete. Kept the tiny
    optional title input and the "N sentences · P% read" meta — small
    utilities the reference didn't forbid. → Change: `components/Library.tsx`.

33. **Removed: `App.css` never existed; unused template files are gone** from
    the earlier cleanup — nothing user-facing depended on them.

## v2 test-pass fixes (Oct 19, 2026 — caught by the new e2e suite)

34. **Fixed: stale-closure popup actions (real bug, not a test bug).**
    `toggleMarkKind`/`doCopy` were `useCallback(..., [bookId])` but read the
    sentence via a helper closed over the first render, where `book` was
    still null — so every row click silently no-op'd. They now close over
    the fresh `current` with `[bookId, current]` / `[current]` deps and the
    helper is gone. Lesson: never eslint-disable exhaustive-deps on a
    callback that reads render state. → Change: `Reader.tsx` popup actions.

35. **Fixed: out-of-range jump hid its own hint (real bug).** `gotoPage`
    always closed the jump sheet, so the clamp hint never rendered.
    Out-of-range jumps now set position directly, keep the sheet open, and
    rewrite the input to the clamped value. → Change: `submitJump`.

36. **Fixed: bottom-nav hover/tap race (real UX bug).** Mousemove into the
    hot zone revealed the bar, then the tap toggled it straight back off —
    a desktop user would hit the same. Hot-zone taps now always reveal;
    dismissal is the 2.5s auto-hide. → Change: `onPointerUp`.

37. **Fixed: hidden bar wasn't hidden (a11y/test correctness).** Opacity 0
    alone still counts as visible (and to assistive tech). Now
    `visibility: hidden` with the transition delayed 250ms so the fade
    completes first. → Change: `.bottom-nav` in `index.css`.

38. **Test call: whole e2e file runs at 390×844.** The bottom-nav hot-zone
    and middle-third tap are viewport-relative; Playwright's default
    1280×720 put the hot-zone tap outside the window. Phone viewport is
    also the product's real target. → Change: `test.use` in reader.spec.ts.

39. **Test call: Copy asserts the RAW sentence text.** The heading renders
    uppercase via CSS, so `innerText` is "THE MIDNIGHT STAIRCASE" while the
    clipboard correctly gets "The Midnight Staircase". Asserting raw text
    is the right behaviour — pasting shouldn't inherit display casing.

## v3: the user's own reader mechanics (Oct 19, 2026)

40. **v3 throws away v2's three-zone stage; the reader IS his track now.**
    Nahom rejected the v2 stage outright ("keep only the extractor; ALL the
    UI is his"). The reader is now a faithful port of his code: item stream,
    per-part stepping via his exact splitS, the translating track with his
    place() centring rule (current part centred when a multi-part item is
    taller than half the stage), his visibility window (far beyond I±1 / I−2),
    his input (wheel 200ms lock / |deltaY|≥4, keys, 30px touch swipe,
    click-first). Ported algorithms live in lib/parts.ts (splitS, exact) and
    lib/types.ts (paginate rule, stepParts, progressOf). The engine that stays
    ours: extract/segment/structure (file parsing), plus the v2-approved
    chrome (Settings page, auto-hiding nav, one-card popup).
    → Change: components/Reader.tsx rewritten; lib/types.ts rewritten.

41. **Pagination = his rule for EPUB/TXT/paste: heading or 7 items.**
    The v2 14-sentence pages are gone. PDFs keep real extracted pages.
    Headings are never sentence-split. Old stored books (pages shape) migrate
    transparently on load (migrateBook in lib/types.ts, persisted once).
    → Change: paginateBlocks/assignPages in lib/types.ts.

42. **Position is (item, part), persisted as such.**
    Old {page, sent} progress records convert to the first item of the
    saved page (migratePosition). v2's sentence-id marks no longer match the
    new "itemIndex:partIndex" part keys — they simply don't render, which is
    acceptable for a pre-release; no migration was built. Marks die with the
    book as before. → Change: lib/db.ts marks store key format.

43. **No page popup at all — inline editable page number in the top bar.**
    The bar reads `Page [ 3 ] / 10 · 42%` where the number is a borderless
    field: click/focus selects it, type, Enter or blur commits (clamps
    1..N, jumps to that page's first item), Esc cancels and restores,
    non-numeric reverts. Both jump sheets (his slider sheet and v2's typed
    sheet) are deleted, section/bookmark lists with them. The progress
    percentage is item-based like his.
    → Change: the page-input in Reader.tsx.

44. **Popup: his anchor + trigger, our one-card + stagger.**
    Double-tap the active part (or single tap on a single-part sentence)
    opens ONE card anchored below the item (+16px, flips above near the
    bottom, right-aligned, clamped) — his openPop math exactly. The three
    rows (Highlight/Bookmark/Copy, icon + label) keep v2's staggered
    entrance. Actions target the PART: highlight wash and bookmark dot render
    on that part span only; copy copies the part's text. Esc closes; stepping
    closes (his code ignored arrows while the popup was open — wheel/swipe/
    tap steps now also dismiss it, which is the saner reading of his intent).
    → Change: popup block in Reader.tsx.

45. **Popup focus effect (his .fx): blur chrome, zoom the sentence.**
    Opening the popup adds .fx to the reader root: top bar / progress /
    bottom nav blur(10px), non-current sentences blur(9px), non-active parts
    of the current sentence blur(7px), and the current sentence scales 1.06
    (origin left center) — the "floating" feeling from his CSS. Filter and
    transform transitions are ~0.3s; closing removes it all. Ported exactly
    from his #reader.fx rules, mapped onto our class names.
    → Change: .fx rules in index.css; `fx` class toggle in Reader.tsx.

46. **Clicks are the primary input; taps never fight the nav.**
    His click tree is ported verbatim: adjacent item → jump (forward = part
    0, back = last part), other part of current sentence → select it, double
    tap / single-part tap → popup. The bottom hot-zone tap reveals the nav
    instead of stepping (v2 behaviour kept). `cursor: pointer` on sentences
    is a deliberate addition (his CSS has none) so desktop users see the
    clickability. → Change: native click handler in Reader.tsx.

47. **Spacing kept at his values: 3 sentences visible, lots of air.**
    Item margin `max(2.6em, 18vh)` + the far window (I−2..I+1) + the stage
    mask reproduce his "one top, one middle, one bottom" look. The old v2
    desktop 56rem content cap is gone (his CSS has none). Verified in the v3
    screenshots rather than by assertion.

48. **Bottom nav «/» = his chapter jumps (heading items).**
    « = nearest heading item before the current one (else item 0), » = first
    heading item after it; both land at part 0. ‹/› = prev/next page's first
    item. The v2 auto-hide mechanics (hover, hot-zone tap, page-change
    reveal, 2.5s hide) are unchanged.
    → Change: chap() in Reader.tsx.

49. **Settings model aligned to his S, Lexend added properly.**
    Highlight palette is now his exact 5 oklch colours (indigo .62/.2/266,
    amber .85/.17/90, green .75/.18/150, red .68/.2/20, pink .72/.19/330).
    Font chips render in their own typeface (his detail). Lexend ships
    offline: @fontsource/lexend added as a dependency, its 400/600 latin
    woff2 copied by scripts/copy-fonts.mjs and @font-face'd in index.css.
    Font order: Geist, Noto Serif Georgian, Geist Mono, Lexend, System.
    → Change: lib/settings.tsx, Settings.tsx, copy-fonts.mjs, index.css.

50. **Long-sentence shrink tiers are gone.** v2 shrank the font for long
    sentences; v3 doesn't need it — his part-splitting + part-centring
    handles long items by design. Current item is always the main size.

## v3 additions: notes + Saved view (Oct 19, 2026, pre-launch)

51. **Popup card now has four rows: Bookmark, Highlight, Note, Copy.**
    Note was the user's explicit addition; the order is his. The stagger
    extends to 200ms for the fourth row. Tapping Note swaps the card to a
    small editor (textarea prefilled with the existing note, Save / Cancel /
    Delete when a note exists) and back to the rows on save.
    → Change: rows array + note editor in Reader.tsx.

52. **Notes are per-part, stored additively in the marks store.**
    PartMark gains `note: string | null` (old records without the field read
    as null); setNote() upserts, and deletes the record entirely when all of
    highlight/bookmark/note are empty, to keep the store tidy. No DB version
    bump needed — the store shape is unchanged.
    → Change: lib/db.ts (PartMark.note, setNote).

53. **Note indicator: a small dot in the highlight colour after the part.**
    Bookmark already owns the primary-colour dot; the note dot uses
    --lr-hl so the two marks are visually distinct but related. Tasteful and
    tiny at trail sizes. → Change: .pt.nt::after in index.css.

54. **Saved view: one place for a book's bookmarks, highlights and notes.**
    Dedicated screen listing every marked part in reading order: type icon(s)
    (bookmark/highlight/note, in popup row order), the part's text snippet,
    its page number, and the note text when present. Tapping an entry opens
    the reader at that exact item+part (implemented by persisting the
    position first, then opening the book — the reader restores it as the
    saved position). Entry points: bookmark icon in the reader top bar, and a
    bookmark icon in the library header that opens Saved for the last-open
    book (falling back to the newest book; hidden when the library is
    empty). Empty state: "Nothing saved yet — …". No delete-from-list (he
    said skip unless trivial — deletion lives in the popup editor).
    → Change: components/Saved.tsx, App.tsx (saved view + jumpToSaved),
    Library.tsx (header button), Reader.tsx (top-bar button).
