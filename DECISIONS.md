# DECISIONS.md — Lyric Reader

Every judgement call made while Nahom slept. Each entry: what I chose, why,
and how to change it. Nothing here is load-bearing — veto anything.

## Reader look & feel

1. **Muted trail = white at 28% opacity, NOT `--muted-foreground`.**
   The design system's dark `--muted-foreground` (0.72 lightness) renders as
   medium grey — far too loud next to the mockup's ~25–30% white trail.
   Trail blocks use `#fff` at `var(--trail-opacity: 0.28)` with a fade mask.
   → Change: edit `--trail-opacity` in `app/src/index.css`.

2. **Primary indigo (266) never touches reader body text.**
   It's reserved for library UI: buttons, progress bars, the "LYRIC READER"
   eyebrow, focus rings. The reader stays pure black + white only.
   → Change: it's just usage discipline; no token to flip.

3. **Current-sentence auto-shrink tiers.**
   Mockup shows one huge sentence; long sentences must not overflow.
   ≤90 chars → 2.6rem, ≤170 → 2.1rem, ≤280 → 1.7rem, longer → 1.4rem,
   all × the user's font-scale (0.8–1.4, A−/A+ in the overlay).
   → Change: `currentFontSize()` in `app/src/components/Reader.tsx`.

4. **Sentence transition: 300ms ease-out, rise + settle.**
   `translateY(10px) scale(0.985)` → rest, opacity 0.35 → 1.
   Transform/opacity only — no layout work per advance, so no jank.
   Disabled under `prefers-reduced-motion`.
   → Change: `@keyframes sentence-in` in `app/src/index.css`.

5. **One sentence per gesture, guaranteed by construction.**
   Navigation uses functional `setPos(p => step(pages, p, dir))` so rapid
   gestures can't skip. Wheel input is locked for 600ms after each step;
   taps are split into thirds (top = back, bottom = forward, middle = overlay);
   pointer swipes need 48px vertical travel. Keys: arrows/space/page keys.
   → Change: constants at the top of `Reader.tsx`.

6. **Headings render in the serif face when current.**
   Gives chapter titles a "title card" moment; in muted blocks they stay
   small like everything else. (Serif file is Noto Serif Georgian 600,
   self-hosted — see 12.)

7. **Bullet hairlines: nested levels only.**
   Level-0 bullets get indent + no hairline (their "parent" is prose, and a
   line to nowhere looked wrong). Nested bullets (level ≥ 1) get a 1px hairline
   at the parent's indent, white at 22% — the thread-line effect.
   Muted blocks use a `•` marker + indent instead of hairlines.
   → Change: `Reader.tsx` (`bullet-hairline`) and `TrailLine`.

8. **Desktop: content column capped at 56rem, centered.**
   The mockup is a phone; at laptop widths uncapped text ran 900px+ wide.
   Phone keeps the mockup's ~12% side margins (`max(1.5rem, 12%)`).

9. **Overlay: hidden until you tap the middle third, auto-hides after 3.5s.**
   Contains ← Library, title, `Page x of y · z%`, thin primary progress bar,
   and A−/A+ font controls. Nothing else lives on the reader screen.

10. **End of book: clamps.** No "finished" screen in v1 — advancing past the
    last sentence just stays put. (Easy to add later if wanted.)

## Pagination & position

11. **EPUB / TXT / paste: ~14 sentences per page. PDF: one reader page per PDF page.**
    The 14-sentence chunk keeps the muted trail from becoming a wall while
    keeping page turns infrequent. PDF pages are natural boundaries already.
    → Change: `SENTENCES_PER_PAGE` in `app/src/lib/extract.ts`.

12. **Reading position = (page, sentence) in IndexedDB, saved debounced
    (500ms) + flushed on `pagehide`. The last-open book id is remembered in
    localStorage, so reopening the app drops you straight back into reading.**
    → Change: `app/src/lib/db.ts`, `App.tsx`.

## Extraction

13. **EPUB parsed with jszip + a hand-rolled OPF/spine walker, not epubjs.**
    Smaller bundle, fully deterministic, no extra dependency. Handles
    h1–h6, p/div/blockquote, nested ul/ol with depth.
14. **PDF text rebuilt by grouping glyphs into lines (y-tolerance 2.5px).**
    Good for single-column prose; two-column layouts may read across columns —
    documented as a known limit.
15. **Sentence splitter = `Intl.Segmenter` + abbreviation merge rules**
    (Dr., e.g., Fig., decimals, initials, ellipses). Rules live in
    `app/src/lib/segment.ts` and are unit-tested.
16. **DOCX not included in v1.** Spec listed it as "if time"; PDF/EPUB/TXT +
    paste-text cover the MVP. Say the word and I'll add mammoth.js.

## Fonts, icons, PWA plumbing

17. **Fonts self-hosted in `/fonts`, precached by the service worker:**
    Geist Regular + SemiBold and Geist Mono Regular from the `geist` npm
    package; Noto Serif Georgian 600 (latin + latin-ext subsets) fetched from
    Google Fonts at build time. If a file ever goes missing the stacks fall
    back to system fonts — the app still works.
18. **Icons generated by a zero-dependency Node script**
    (`app/scripts/make-icons.mjs`): "lyrics bars" motif — five primary-indigo
    bars on pure black, 192/512 + maskable-512 with safe-zone padding.
19. **Service worker via `vite-plugin-pwa` (generateSW).**
    Precaches everything including the pdf.js worker (cache cap raised to
    12MB); `navigateFallback: index.html` so reloads work offline.
    Chose the plugin over a hand-rolled SW for reliability.
20. **App is dark-only** (`<html class="dark">` forced) — the whole product is
    the black reader; a light theme would fight the mockup.

## Content

21. **Sample book "Sample — The Midnight Staircase"** (60 sentences, 5 pages)
    is original prose written for testing: paragraphs, headings, nested
    bullets. Seeded once on first run (guarded against double-seeding).

## v3.2: tap-outside dismissal for the action popup (Oct 19, 2026, morning)

Bug from his phone: the Bookmark/Highlight/Note/Copy popup opened fine but
could not be dismissed by tapping elsewhere — the only way back was Esc.
Root cause: the full-screen `.pop-layer` backdrop had no tap handler at
all; taps landed on it and died there (the stage's own click handler sits
below the layer's z-index, so it never saw them either).
Change (Reader.tsx, one clear mechanism): a capture-phase `onPointerDownCapture`
on the reader root. While the popup is open, any press outside the card closes
it and stops propagation; taps inside the card (`menuRef.contains`) are
untouched so rows, the note editor, Save/Cancel/Delete keep working. A second
tap on the sentence itself counts as "outside the card" and also just closes —
no stacked states.
Swallow rule: the dismissed tap must not also step, select, reveal chrome, or
fire a chrome button. A capture-phase stopPropagation kills the pointerdown
leg, and a 450ms `suppressUntil` timestamp ignores the click that follows it
(stage onClick + every chrome button + page-input focus check it). Row
behaviour unchanged: Bookmark/Highlight toggle, Copy shows "Copied", Note
save/cancel/delete and Esc keep closing exactly as before. The fx blur is
tied to the popup-open state and clears on close as it always did.

## v4: selection + Meaning + Words (Oct 19, 2026)

Selection wake-up: sentences stay `user-select:none` everywhere except the
current sentence's part spans — `.s.cur .pt` gets a scoped
`user-select:text` override, so selection can only ever begin where reading
happens. The wake-up listens to the native `selectionchange` event (not
click-drag timers): any non-collapsed selection fully inside the current
item raises the pill; a collapsed selection or one outside the current item
hides it. The pill is positioned from the selection's bounding rect,
clamped to the viewport (top - 60, min 8px top, horizontal clamp).

Suppression while a selection is live: the same swallow pattern as the
action popup — wheel, touchmove, hot-zone clicks, arrow keys and the popup
open path all bail while `sel`, the meaning card, or the Ask sheet is open.
Tap-anywhere-else collapses the selection via the root capture handler and
swallows the gesture (same 450ms suppress), so it can never also step.
Esc unwinds topmost-first (selection -> meaning card -> Ask sheet -> popup).
Android shows its own native selection menu alongside ours — accepted for
v1; our pill is the feature path. Honest gap: no physical Android device
was available to verify the long-press + native-menu interplay; headless
Chromium covers the selectionchange path via programmatic ranges only.

Meaning card: reuses the popup card styling + the same anchor math
(extracted into `anchorCard`), and re-anchors after the lookup resolves
(content height changes loading -> definition). Single word: dictionaryapi
first, one lemmatizer retry on 404; phrase (2+ words) or dictionary miss:
Gemini JSON if a key is set, else a calm "phrases need the AI" state with a
Settings link. Single word WITH a key also pulls the "as used in this
sentence" line from Gemini in the background (cached per word+sentence) —
the dictionary result renders instantly, the AI line appends when it
arrives. Offline/network failure is a plain offline state, no crash.

Vocab: one IndexedDB store, dedupe by `norm` (lowercased trimmed text);
re-saving UPDATES the context fields (book/page/sentence) to the latest
but KEEPS the original `savedAt`/`dayKey` — the first time you learned a
word stays under that day's group. Saved occurrences get a faint dotted
underline via `decorateText` (longest-norm-first, word-boundary,
case-insensitive) applied only to rendered part spans.

Words view: a segmented `Saved | Words` switch INSIDE the Saved view
(per-book, matching his marks model) rather than a new top-level screen —
one bookmark icon path, no parallel places to look. Rows group by day
(Today / Yesterday / "Mon 12 Oct" + count); row = word, one-line first
definition, muted "book · p.N" source; tap reuses the Saved jump mechanism
to land on the exact item+part. Delete per row with a small ×, no confirm
(consistent with app patterns — undo not required).

## v4.1: custom selection — the native Selection is never created (Oct 19, 2026)

His screenshot: Android Chrome's native selection toolbar (Define / Copy /
Select all / Web search) appeared over our UI, plus Google's own definition
sheet popped. That toolbar exists because we created a native Selection
(`user-select: text` on the current sentence + `selectionchange` listener).
No amount of styling removes it — it is the OS/browser's, not ours.

Decision: kill native selection entirely. No element in the reader is
`user-select: text` anymore (everything `user-select: none`, plus
`-webkit-touch-callout: none` so the long-press callout bubble never shows).
Selection is rebuilt from scratch:

- Long-press (~450ms, <10px movement) on a part span of the CURRENT item ->
  `document.caretRangeFromPoint` (fallback `caretPositionFromPoint`) ->
  expand to word boundaries in that text node (scoped to the current item).
- Paint via the CSS Custom Highlight API:
  `CSS.highlights.set("lr-sel", new Highlight(range))`, styled with
  `::highlight(lr-sel)` in his highlight wash. Native Selection is never
  touched, so no handles, no magnifier, no Google bar — only our
  Meaning/Copy pill, positioned from `range.getBoundingClientRect()` exactly
  as before.
- Drag (pointermove while the press is still down, anchored at the word
  start; or a fresh press starting inside the painted selection, anchored at
  the far end) extends the loose end to the word boundary at the pointer —
  phrases/idioms in one gesture. Selection persists on pointerup.
- Tap outside dismisses (existing capture-phase swallow machinery; the
  capture handler lets presses that START inside the painted selection
  through so re-drags work). Esc clears. While a selection is active — or a
  long-press is pending, or a drag is in flight — all stepping input stays
  suppressed (wheel/touchmove/click guards).
- Caught in testing: the first version suppressed the synthetic click after
  EVERY pointerup with a pending long-press timer — which killed normal
  taps (double-tap-to-popup broke). Now only a selection that actually
  STARTED (long-press fired / drag in flight) suppresses the following click.
- Fallback: if `CSS.highlights`/`Highlight` is unavailable (old browsers),
  the word still selects and the pill still works — just no paint and no
  drag-extend. Logged here as the known limitation; nothing else degrades.

New pure module `lib/selection.ts` (`caretRangeAt`, `wordRangeAt`,
`extendSelection`, `paintSelection`) so the geometry is unit-testable and
Reader.tsx stays a thin wiring layer.

## v4.1: anchored-card clamping — cards can never leave the viewport (Oct 19, 2026)

His screenshot: the note editor hung off the right edge, Save cut off.
Root cause: `.menu` had no max-width, so the note textarea's `width: 100%`
made shrink-to-fit balloon the card to full viewport width; the anchor
clamp then pinned `left: 16` and the right side overflowed by 16px.

Decision, three layers (all of them, not one):
1. CSS caps: `.menu` gets `max-width: min(340px, calc(100vw - 24px))`,
   `max-height: calc(100dvh - 32px)` with internal scroll, and
   `box-sizing: border-box`. Internals (`.note-editor`, `.note-textarea`)
   are `width: 100%; max-width: 100%; box-sizing: border-box` — a child can
   never stretch its card again.
2. `anchorCard` math rewritten as a guarantee: measure, clamp the measured
   size to the viewport first, then hard-clamp both axes to ≥16px margins —
   whatever the anchor sentence's size/position. The pill gets a real
   post-render horizontal re-clamp (measured width, not the old
   `innerWidth - 190` guess).
3. A ResizeObserver re-runs the clamp whenever a card's own size changes.
   This caught a real bug in testing: the bundled webfont arrives AFTER
   anchoring, reflows the text, and widens the card past the clamped
   position (measured 214px at anchor, 230px after fonts — 10px off the
   right edge). Content/async growth is covered the same way.

## v4.2: official Gemini docs audit + key-import link + timeouts + raw errors (Oct 19, 2026)

Nahom sent Google's own REST example (his curl: `POST
/v1beta/models/gemini-flash-latest:generateContent`, header
`X-goog-api-key`) and asked that our integration match the official docs
exactly. Pages checked (fetched 2026-10-19): quickstart, text-generation,
api-key, and the classic REST surface his curl implies. Findings:

1. **Key header** — docs use lowercase `x-goog-api-key`; ours already
   matched exactly. HTTP headers are case-insensitive anyway; no change.
2. **Key types** — the API is transitioning from standard keys (AIza…)
   to authorization/auth keys (**AQ.…**, bound to a service account,
   restricted to the Generative Language API by default). Nahom's key is
   an auth key; it authenticates with the SAME `x-goog-api-key` header, so
   the app needs no format logic: it accepts any pasted key string
   (length ≥ 1 for storage, ≥ 8 to accept from a setup link).
3. **`gemini-flash-latest`** — Google's documented rolling alias for the
   newest Flash. Our picker puts it second (after explicit
   `gemini-3.5-flash`), and it is now the HARD fallback: no stored model
   + failed discovery calls the alias directly, and a 404 on any model
   re-discovers once then tries the alias once before surfacing an error.
4. **Classic request body is already exact**: `contents[].parts[].text`,
   `generationConfig{temperature,maxOutputTokens,responseMimeType}`, and
   `system_instruction` (snake_case per the reference). `models.list`
   response handling matches (`models[].name`,
   `supportedGenerationMethods`; we take pageSize=100, no pagination —
   deliberate: a one-page flash list is all we need).
5. **NOT migrating to the new Interactions API** (`POST /v1beta/interactions`
   with `{model, input, system_instruction, generation_config}`), even
   though the current docs lead with it: Nahom's phone already reached
   `generateContent` (a routed 404 on the model name proves the endpoint
   is alive for his key), and the new surface's response shape can't be
   verified from this VM. Logged as a future-migration candidate only.

His v4.1 phone report (key "not returning", dictionary-unreachable state)
added three small resilience items in the same pass:
- **`#k=<key>` setup links**: app load parses the hash fragment, stores
  the key in the existing localStorage slot, strips the fragment via
  `history.replaceState` (it must not linger in the URL/history), then
  auto-runs discovery and toasts `Gemini key saved — using {model}` (or
  the real error). Defensive: only values ≥ 8 chars accepted.
- **Timeouts + retry**: every Gemini call (discovery, generateContent)
  has a 20s AbortController timeout and ONE retry on network

- **Google's real error text**: failures now show the API's own
  `{error.message}` (trimmed to 140 chars) appended to our mapped
  messages, in the Settings test result and all AI error states — a
